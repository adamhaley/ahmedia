## Project Overview

This is the frontend for AH Media.ai: a static landing page (glowing teal/cyan wordmark
aesthetic) with a chat widget powered by n8n webhooks. The site is being built out further
from this minimal starting point.

The frontend (`index.html`, `styles.css`, `scripts.js`) is **generated output** from
[Codette](/opt/homebrew/var/www/codette), Adam's declarative static-site generator — do not
hand-edit these files directly. Edit the source instead:
- `codette/themes/ahmedia.css` — color tokens (teal/cyan palette) and the glow text-shadow
  applied to `.display-title`, `.text-accent`, `.site-brand`, `.footer-brand`
- `codette/patterns/index.mjs` — the generic `hero` pattern (supports an optional `accent`
  span and an optional side `panel`) and the `chatWidget` utility
- `codette/sites/ahmedia/site.json` — this site's content spec

Then rebuild with `cd /opt/homebrew/var/www/codette && npm run build -- ahmedia` and copy
`codette/output/ahmedia/{index.html,styles.css,scripts.js}` back into this repo's root.

## Architecture

### Frontend Structure
- **index.html**, **styles.css**, **scripts.js**: generated by Codette (see above) — a plain
  `hero` section for the "AH Media.ai" wordmark (glow comes from the theme, not a bespoke
  pattern), plus the floating chat widget markup/styles and its behavior script (streaming
  NDJSON parsing, typing indicator, namespace handling).

An earlier iteration of this rebuild used a bespoke `neonRings` pattern (an animated glowing
ring cluster meant to mirror the original hand-tuned GSAP hero). It was abandoned and removed
from Codette entirely — the ring positions never translated cleanly into Codette's layout
system, and it wasn't worth the effort for what's meant to stay a simple demo page. If ring
artwork comes back later, treat it as a fresh design rather than resurrecting that pattern.

### Backend Integration
- **PHP webhook proxy**: Browser traffic goes through local PHP endpoints that forward to n8n
  - Chat proxy: `/api/chat.php`
  - Upload proxy: `/api/upload.php` (kept for future use; no upload UI is currently wired up)
  - Shared secret loaded from `.env` via `N8N_WEBHOOK_KEY`
  - Header name loaded from `.env` via `N8N_WEBHOOK_HEADER_NAME`
  - Optional upstream overrides: `N8N_CHAT_WEBHOOK_URL`, `N8N_UPLOAD_WEBHOOK_URL`

## Key Features

### Chat Interface
- Real-time messaging with typing indicators, streaming NDJSON response parsing
- Collapsible chat container with reopen functionality
- A `namespace` value is auto-generated into `localStorage` on first load (no upload step
  required — see `chatWidget` utility in Codette's `patterns/index.mjs`)

### Hero
- Plain Codette `hero` pattern; the glow look comes entirely from theme CSS
  (`.display-title`/`.text-accent` text-shadow), so it's not tied to any bespoke pattern
- No scroll-linked animation of any kind — normal document flow, no GSAP/ScrollTrigger

## Development Notes

### Environment Variables
- `N8N_WEBHOOK_KEY`: Required for authenticating proxy requests to n8n
- `N8N_WEBHOOK_HEADER_NAME`: Header name used for n8n webhook auth
- `N8N_CHAT_WEBHOOK_URL`: Optional override for the upstream chat webhook
- `N8N_UPLOAD_WEBHOOK_URL`: Optional override for the upstream upload webhook

## Webhook Configuration

The browser should call local proxy endpoints instead of hitting n8n directly:
- `/api/chat.php` forwards JSON chat requests
- `/api/upload.php` forwards multipart file uploads
- n8n should validate the header configured by `N8N_WEBHOOK_HEADER_NAME` on both workflows

## Browser Compatibility

The generated frontend uses modern JavaScript features including:
- Async/await for API calls
- Fetch API for HTTP requests (including streaming response bodies)
- DOM manipulation with modern selectors
- localStorage for client-side persistence
- `crypto.randomUUID()` (falls back to a timestamp if unavailable)
